# The Familiar — Changelog

This changelog summarizes changes that can be verified in the repository's commit history, current source, tests, and project documentation. The **Unreleased** section describes the current uncommitted working tree being prepared for review; it does not imply that those changes have already been merged or released. Historical provenance is included where Git history supports it. Shared-team working-tree edits are not attributed to an individual.

## Unreleased — 2026-10-15

### Current AI and browser-runtime pass — 2026-10-15

#### MAJOR UPDATES

- **More reliable visible-player acquisition and post-QTE escape.** The Familiar confirms unobstructed sight independently of noise suspicion, reacts faster at close range, and now transitions through collision-safe stun, retreat, and recovery after a successful QTE. Configurable sight, retreat, and cooldown tuning lives in `systems/monster/monster_tuning.gd`; behavior and state ownership are in `systems/monster/monster_controller.gd` and `game/integration/main_game.gd`.

#### HIGH PRIORITY UPDATES

- **New Game startup no longer reveals gameplay before instructions.** Gameplay remains hidden until its story/wake-up overlay is ready, then the existing flow proceeds. The main-menu scene handoff is in `game/ui/main_menu.gd`; integration signals are in `game/integration/main_game.gd`.
- **Main-menu audio now follows browser gesture rules.** The menu reuses the existing exploration track on the Music bus after the first real keyboard or mouse input, then fades it out/in across the opening sequence, gameplay, and return to menu. No autoplay restriction is bypassed and no extra track was added.

#### MEDIUM PRIORITY UPDATES

- **Reduced repeated monster navigation reachability work.** Player-route checks are cached and refreshed on a configurable interval instead of being recomputed every physics frame during sight contact. The build does not claim an overall FPS gain; no before/after frame-rate profile was available.
- **Local Web build and browser startup were checked.** A fresh Godot 4.7.2 release export completed, the generated files served over local HTTP, and a headless Chrome screenshot showed the title menu and house backdrop. Interactive browser gameplay and audible output were not fully playtested.

#### MINOR UPDATES

- **Regression coverage expanded and stabilized.** Frontend, house, monster, Familiar, and combined integration suites now exercise stationary direct sight, successful QTE retreat, hidden gameplay during New Game setup, and menu audio activation. The legacy handoff assertion waits for the asynchronous controller transition rather than sampling a single fixed frame.
- **Deployment size record refreshed.** Current local HTML, JS, WASM, and PCK total 85,026,737 bytes (about 81.1 MiB). Export output remains in ignored `web-build/` and is not staged.

### MAJOR UPDATES

- **Four-level realized house and playable escape route.** Consolidated the existing procedural house with the Kenney house/furniture assets into the active game, preserving the basement, ground floor, second floor, attic, exterior landing, stairs, navigation, hiding spots, progression objects, and escape route. The latest layout pass reorganizes the rear wing and removes redundant upstairs study/reading divisions and duplicated basement laundry props. The design is documented in `game/house/HOUSE_LAYOUT_PLAN.md`; generation and placement live in `game/house/house_builder.gd` and `game/house/house_environment.gd`. The house suite exercises traversal, objects, stairs, hiding, navigation, and escape.
- **Integrated first-person game flow.** The project now launches through the title menu, instantiates gameplay only after New Game, presents the story pages and bedroom wake-up, then connects exploration, capture, and escape outcomes. The main integration is in `game/integration/main_game.gd`, `game/environment/escape_environment.gd`, and `game/environment/first_person_player.gd`; scene selection is in `project.godot`. Continue is deliberately disabled because there is no gameplay save/load system.
- **Familiar hunter and character asset pipeline.** The existing mother-like entity is integrated with patrol/routine, suspicion, investigation, pursuit, last-known-position search, hiding checks, doors, stairs/navigation, capture, and recovery behavior. The behavior controller is in `systems/monster/monster_controller.gd`, with household behavior in `systems/familiar/familiar_controller.gd` and tunables in `systems/monster/monster_tuning.gd`. Earlier committed model work is recorded in history, including the Everyday Jane model research/refinement and the later face/mesh refinements. No replacement controller was added.
- **Shared menu, HUD, and outcome system.** The title menu and in-game UI use a common horror presentation and maintain separate front-end, gameplay-HUD, pause, confirmation, QTE, and ending layers. The menu has New Game, disabled Continue, Settings, Controls, Credits, and Quit; the in-game menu has Objective, Controls, Settings, Audio, Resume, restart confirmation, and return-to-menu confirmation. Main implementation is in `game/ui/main_menu.gd`, `game/ui/main_menu.tscn`, and `game/ui/game_ui.gd`.
- **Automated browser-game deployment.** GitHub Pages is configured to use GitHub Actions, and `.github/workflows/deploy-web.yml` builds the project with Godot 4.7.2, runs its verification suites, exports a single-threaded Web build, and deploys the artifact to Pages. The first workflow run (38830531879) succeeded for commit `e5ee6b5`; the root and core game assets at `https://jcodes101.github.io/Halloween_Game_Project3_COMP440/` returned HTTP 200. This verifies deployment and asset delivery, not interactive browser gameplay; details are in `docs/WEB_DEPLOYMENT.md`.

### HIGH PRIORITY UPDATES

- **Capture survival QTE and stun escape.** Every physical close encounter enters the five-second QTE path before capture presentation, independent of battery state. A three-key sequence is generated from Q/E/R/F, with a configurable seed and sequence length and avoidance of an immediate identical repeat when possible. Success triggers a camera shove and a procedural Familiar recoil/stagger with temporary recapture protection; failure goes through the existing capture ending. The event path is connected by `game/integration/main_game.gd` and presented by `game/ui/game_ui.gd`; monster behavior is in `systems/monster/monster_controller.gd`. Tests exercise the real close-encounter callback as well as QTE outcomes.
- **Flashlight and randomized rechargeable batteries.** The camera-mounted spotlight has switch state, configurable beam, drain, low-charge flicker/depletion, and recharge signals. Six to eight curated pickups are selected per run, with coverage across all four levels and a reproducible optional seed; collecting one uses the existing E prompt and restores up to 35 percentage points, clamped to maximum. See `game/environment/flashlight_controller.gd` and `game/house/house_environment.gd`.
- **Seven-track adaptive horror audio.** The scene-local manager discovers exploration, investigation, chase, hiding, QTE, escape-ending, and capture-ending files by stem and supported extension. AI states select and crossfade the four looping moods; hiding requires both an active hiding state and nearby threat; QTE/ending cues are one-shots with ending priority. Tracks route through `Music`, preserving Music/Master controls and tree pause. See `game/integration/dynamic_horror_music.gd` and `assets/audio/music/README.md`. Track redistribution licenses/attribution are not documented yet.
- **Familiar awareness, investigation, and recovery.** The controller responds to sight/hearing and gameplay evidence, tracks a last credible location, searches after line-of-sight loss, checks witnessed hiding locations, opens supported ordinary doors, and respects capture/stun state. The monster suite covers core behavior; actual chase feel and audiovisual fairness still need a human gameplay pass.
- **Bedroom opening, doors, and deliberate run navigation.** New runs start at the upstairs player bedroom; the story introduction leads into a first-person waking sequence with eyelid overlays and camera movement. The bedroom door starts closed. Ordinary room doors use interaction/animation/collision and navigation links; special escape locks remain controlled by progression. Relevant code: `game/ui/game_ui.gd`, `game/integration/main_game.gd`, and `game/house/house_builder.gd` / `house_environment.gd`.
- **Production Godot Web build and Pages workflow.** The workflow checks out the project, installs the matching editor/templates, runs frontend, house, monster, Familiar, and integration tests, verifies the exported loader/runtime/PCK files, then uses GitHub's Pages artifact/deployment actions. The build uses the project's Compatibility renderer and disables Web threads, avoiding cross-origin isolation requirements. Browser interaction still requires a live browser test.

### MEDIUM PRIORITY UPDATES

- **Living-room space and circulation.** The ground-floor west living room changes from 9.8 × 4 m to 9.8 × 5 m by moving an interior partition, a 25% floor-area increase without changing the exterior shell or main stair approach. Sofa hiding remains within the bounds, and the suite checks the navigation route. Layout source: `game/house/house_builder.gd`; plan: `game/house/HOUSE_LAYOUT_PLAN.md`.
- **Environmental presentation.** Added an animated CRT-screen shader, lightweight stove steam, low-cost selected-light dips, CRT glow/static, and darkened house illumination. These are implemented in `game/house/crt_screen.gdshader`, `game/house/steam_puff.gdshader`, and `game/house/house_atmosphere.gd`; atmosphere inputs are configured by the house builder. Actual brightness and audio balance need review in a normal visual/audio playthrough.
- **VHS proximity effect.** A screen-space shader responds smoothly to Familiar distance, with stronger scanline/noise/distortion as threat closes. It is layered independently from the HUD. See `game/integration/vhs_proximity_effect.gd` and `game/integration/vhs_screen_effect.gdshader`.
- **Movement and camera feedback.** Added movement-linked head bob/sway, landing/shove response, smooth movement transitions, and player footsteps where the existing sound assets support them. Camera motion is configurable through persistent settings. Main source: `game/environment/first_person_player.gd`; player scene settings: `game/environment/first_person_player.tscn`.
- **Cinematic visual language and typography.** Added a dark/red live house-backdrop menu, restrained button/page transitions, shared serif system-font selection with fallbacks, shared slider/scroll styling, and menu vignette. `game/ui/horror_typography.gd` currently uses installed system fonts rather than a bundled font asset; font appearance can vary by machine.
- **HUD clarity and responsive layout.** The HUD prioritizes hiding state, interaction prompts, objective information, and notifications; displays location and flashlight charge; and provides readable QTE, pause, confirmation, and ending overlays. Front-end validation checks panel bounds at 960×720, 1280×720, and 1920×1080.
- **Lean web export contents.** The Web preset excludes source design previews, documentation, and handoff files while retaining runtime assets. The fresh export's loader, JavaScript, WASM, and PCK total 84,989,861 bytes (about 81.1 MiB); the nine locally modified house preview images remain excluded from this deployment change.

### MINOR UPDATES

- **Verification improvements.** Expanded house and monster assertions and added front-end validation. The legacy integration runner reports passed/failed totals and exits nonzero on failure. The suite counts and warnings observed during this audit are recorded in `docs/DEVELOPMENT_UPDATE_REPORT.md`.
- **Accurate player-facing controls.** Corrected the main-menu QTE help text to say the player follows the displayed sequence instead of implying a fixed Q/R/Q sequence. Updated README control guidance so temporary suspicion keys are identified as developer testing controls, not ordinary player controls.
- **Less timing-sensitive frontend assertion.** The title-lockup check now waits for the existing menu fade to finish before asserting visibility, avoiding a false failure when headless rendering advances only a few frames before the check.
- **Layout and audio guidance.** Added the floor-plan document and track manifest/placement notes. The layout document's contradictory living-room Z bounds were reconciled against the builder constant and its verification assertion. Verification instructions now name `game/main.tscn` explicitly because F5 launches the title menu.
- **Godot resource identifiers and organization.** Added `.gd.uid` / shader `.uid` sidecars for new scripts/shaders, alongside dedicated UI, integration, and test folders. Godot-generated `.import` files and `.godot` cache content remain excluded by `.gitignore`.
- **Selective official Web-template downloader.** `tools/download_godot_web_templates.py` extracts only Godot's two single-threaded Web templates and version marker using validated HTTP ranges, avoiding a 1.28 GB all-platform archive download. The extracted templates passed ZIP integrity checks and produced the local export.
- **Historical technical fixes retained.** The main-line history includes foyer clearance, stair collision/gliding, stair collision correction, basement hiding/lighting, and integrated house/monster/audio changes (commits `5812bf0`, `03e7468`, `e2295f9`, `43251a4`, `f3d6ab4`, and merge `ebb39bc`). Earlier commits document escape-environment setup, monster integration, approved asset preparation, and model refinement. These are established history, not new claims about this uncommitted update.

## Known limitations at audit time

- The seven soundtrack files are present and detected, but their creators, sources, licenses, and attribution requirements are not documented. Confirm redistribution rights before publishing.
- The shared UI uses system serif fonts (Georgia/Times New Roman/Liberation Serif fallbacks); no bundled font was found, so typography portability is not exact.
- The generated menu backdrop is a live render of the current greybox house, not final key art. It is legible and functional but remains low-poly.
- Loop flags are enabled by the manager, but seamless loop points and subjective mix/quality require listening in Godot.
- Automated/headless runs cannot establish that lighting, camera motion, hiding, pursuit, door clearance, QTE readability, or music feel good during a real playthrough.
- The house plan describes approximate procedural bounds, not a survey; the attic and imported furniture meshes need visual review in the editor.
